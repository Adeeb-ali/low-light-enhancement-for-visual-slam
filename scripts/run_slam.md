# ORB-SLAM3 Evaluation Workflow

## Purpose

This document details how **ORB-SLAM3** was utilized to evaluate the effectiveness of the proposed low-light image enhancement model. The core objective was to determine whether image enhancement directly improves downstream robotic vision tasks under challenging illumination conditions.

Specifically, we evaluate improvements in:
* **Base Docker Image:** orbslam3_ready:latest (Image ID: e51c10b9ca5a)
* **ORB Feature Extraction:** Keypoint density per frame.
* **Feature Matching:** Robustness of frame-to-frame association.
* **Map Initialization:** Success and speed of initial map creation.
* **Camera Tracking:** Continuity of localization without tracking loss.
* **Trajectory Generation:** Completeness of the estimated camera path.

## Datasets & Preparation

We evaluated the model across three distinct illumination profiles. Each profile contains both the raw (degraded) sequence and the enhanced sequence generated by our model.

| Dataset Profile | Description | Raw Path | Enhanced Path |
| --- | --- | --- | --- |
| **Daylight** | Normal illumination sequence used as a baseline. | `datasets/daylight` | `enhanced/daylight` |
| **Moderate Low-Light** | Dark sequence where visual features are difficult to detect. | `datasets/moderate` | `enhanced/moderate` |
| **Extreme Low-Light** | Severe illumination degradation with high sensor noise. | `datasets/extreme` | `enhanced/extreme` |

### Dataset Preparation Pipeline

1. **Image Resizing**
All images were resized to **752 × 480** to maintain strict compatibility with the ORB-SLAM3 sensor configuration settings.
2. **Timestamp File Generation (`rgb.txt`)**
ORB-SLAM3 requires an association file containing timestamps for each frame.
*Example `rgb.txt` format:*
```text
0.000000 frame_000000.jpg
0.050000 frame_000001.jpg
0.100000 frame_000002.jpg

```


*Generation Script:*
```bash
python3 scripts/generate_rgb.py <dataset_path>

```

## Docker Workflow

Follow these steps to transfer data, access the isolated environment, and execute the evaluation pipeline.

### 1. Copy Datasets to the Container

```bash
# Transfer raw sequence
docker cp ~/SLAM_PROJECT/datasets/extreme/. orbslam3_work:/workspace/extreme_raw/

# Transfer enhanced sequence
docker cp ~/SLAM_PROJECT/enhanced/extreme/. orbslam3_work:/workspace/extreme_enhanced/

```

### 2. Enter the Container Environment

```bash
docker exec -it orbslam3_work bash

```

### 3. Launch ORB-SLAM3 Evaluation

Inside the container, clear any previous cached paths and run the Monocular TUM execution script:

```bash
# Set environment variables
export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH
cd ~/ORB_SLAM3

# Clear old trajectory outputs
rm -f KeyFrameTrajectory.txt

# Run Monocular SLAM
./Examples/Monocular/mono_tum \
  Vocabulary/ORBvoc.txt \
  Examples/Monocular/TUM1.yaml \
  /workspace/extreme_enhanced

```

## Evaluation Metrics

We quantify SLAM performance using the following metrics parsed from the runtime logs:

* **ORB Features:** Number of ORB keypoints detected per frame. *Higher values indicate richer visual information.*
* **ORB Matches:** Successful matches between consecutive frames. *Higher values indicate stronger frame-to-frame tracking consistency.*
* **Map Initialization:** Success is verified by the instantiation log:
```text
First KF:0
New Map created with X points

```


* **Tracking Robustness:** Monitored via tracking failure logs. Critical indicators of low-light failure include:
```text
TRACK_REF_KF: Less than 15 matches!!
Fail to track local map!

```


* **Trajectory Generation:** Verified by measuring the generated keyframe trajectory file.
```bash
wc -l KeyFrameTrajectory.txt
# Example Output: 58 KeyFrameTrajectory.txt (indicates 58 successfully tracked poses)

```

## Result Interpretation

A successful evaluation run must satisfy the following pipeline lifecycle:

$$\text{First Keyframe Creation} \longrightarrow \text{Map Initialization} \longrightarrow \text{Stable Tracking} \longrightarrow \text{Trajectory Generation}$$

By comparing the tracking continuity and keypoint metrics of **Raw Sequences** against **Enhanced Sequences**, this framework quantitatively demonstrates the performance gains introduced by our low-light image enhancement model on visual SLAM reliability
